# 术语、状态与设计边界

本文定义当前实现和下一阶段设计共同使用的术语。尚未实现的目标状态会显式标记为“规划”，不能据此假定 URL、长文分块、语义图谱或 Obsidian 插件已经可用。完整目标设计见 [Obsidian 优先的采集、交互与知识图谱设计](INTERACTION_AND_GRAPH_DESIGN.md)。

## 当前术语

| 术语 | 含义 | 保存位置 |
| --- | --- | --- |
| 收件箱 | 用户仍可编辑、等待监听的输入文件 | `raw/inbox/` |
| 原始资料 | 已按 SHA-256 归档且不再修改的依据 | `raw/sources/` |
| 归档 | 将收件箱资料复制为原始资料并登记状态 | `.llm-wiki/state.json` |
| 编译 | 对原始资料执行两阶段模型分析与页面生成 | 分析快照和草稿 |
| 草稿 | 尚未写入 Wiki 的候选页面与 Diff | `.llm-wiki/drafts/<run_id>/` |
| 应用 | 基线未变化时将草稿写入 Wiki并更新派生索引 | `draft accept` / 控制中心 |
| 草稿审批 | 决定是否接受一组文件变更 | 草稿状态 `draft`、`applied`、`discarded` |
| 事实核验 | 核实带逐字引句的 `source_claim` 并记录结论 | `.llm-wiki/reviews.json` 与 `wiki/reviews.md` |
| 待补充 | 处理资料缺口、外部查证问题和旧版无引句审核项 | `.llm-wiki/reviews.json` 与 `wiki/reviews.md` |
| 回收站 | 隐藏资料的派生页面和检索结果，可恢复 | `state.json` 的 `trash` 状态 |
| 本机控制中心 | 当前由 `serve` 启动的 Web、API 与 watcher | `tools/wiki.py` |

## 规划术语

| 术语 | 含义 | 计划保存位置 |
| --- | --- | --- |
| 采集记录（Acquisition） | 从文件、URL 或粘贴正文发起的一次来源采集意图 | 版本化 state |
| 来源身份 | 文件来源或规范化 URL，用于识别同一来源 | Acquisition 与归档元数据 |
| 来源快照（Snapshot） | 某次实际取得的不可变正文及稳定元数据 | `raw/sources/` 与状态登记 |
| 正文摘要（content digest） | 规范化正文 SHA-256，用于判断内容是否变化 | Snapshot 元数据 |
| 任务（Job） | 抓取、归档、分块、分析、合并和草稿的可恢复执行 | 版本化 queue |
| 分块（Chunk） | 带标题路径、行号和 digest 的长文分析单元 | analysis 快照 |
| 语义关系（Relation） | 带受控谓词、目标、逐字证据和核验状态的关系 | 页面 `relations` 与 `## 关系` |
| 导航边 | 普通 `[[wikilink]]` 形成的引用，不自动视为语义事实 | Wiki 正文 |
| 来源边 | 页面 `sources` 指向原始资料的证据关系 | Wiki frontmatter |
| Vault ID | 本机服务与插件校验同一知识库的稳定随机身份 | `.llm-wiki/control.json` |
| 能力协商 | 客户端读取 API 版本、功能开关和路由模板后决定可用动作 | `/api/capabilities` |
| 薄客户端 | 只调用 API、展示状态和跳转，不复制业务逻辑的 Web/插件/连接器 | 各客户端代码 |

## 当前状态边界

```text
收件箱 -> 已归档 -> 分析中 -> 草稿待确认 -> 已应用
                              |-> 已丢弃
                              |-> 失败，可重试
已应用 -> 已移入回收站 -> 已恢复
```

规划中的采集会在现有状态前增加：

```text
已提交 -> 抓取中 -> 已形成快照 -> 已归档 -> 分块分析中
       |-> 失败，可重试或改用粘贴正文
```

## 不可混淆的边界

- 归档和分析快照可以立即发生；模型页面、索引、概览、日志和审核/研究项只能在应用草稿时写入。
- 草稿审批不代表事实已核实。只有逐字引句能在原始资料中定位的 `source_claim` 才能进入事实核验；其他问题进入待补充。
- 页面基线变化时应用必须失败；重新生成或人工合并后再继续。
- 页面重新生成保留未知 frontmatter 键和 `## 人工补充`。
- 当前模型输入只覆盖前 14,000 个字符；长文分块落地前，长文完整性是已知限制。
- 当前双链主要表达导航；结构化语义关系与证据图仍处于规划状态。
- 当前没有 Obsidian 自定义插件；现有集成是 Vault、双链和 Web 到 Obsidian 深链。
- 当前 `serve` token 每次启动变化；稳定插件认证和 `control.json` 仍是 Phase 0 规划。
- `serve` 默认已经启动 watcher；`watch` 是无头替代模式，不应对同一 Vault 同时运行两者。
- 图谱始终从 Wiki 页面、来源和关系派生；缓存不是第二套事实源。
- 文件、URL、粘贴、插件和未来连接器都必须进入同一来源、Job、分析和草稿闸门。
- 插件只读发现信息并调用 API；不得直接写 `.llm-wiki/`、运行模型、应用草稿或永久删除。
