# 术语与状态模型

| 术语 | 含义 | 保存位置 |
| --- | --- | --- |
| 收件箱 | 用户仍可编辑、等待监听的输入文件 | `raw/inbox/` |
| 原始资料 | 已按 SHA-256 归档且不再修改的依据 | `raw/sources/` |
| 归档 | 将收件箱资料复制为原始资料并登记状态 | `.llm-wiki/state.json` |
| 编译 | 对原始资料执行两阶段模型分析与页面生成 | 分析快照和草稿 |
| 草稿 | 尚未写入 Wiki 的候选页面与 Diff | `.llm-wiki/drafts/<run_id>/` |
| 应用 | 基线未变化时将草稿写入 Wiki，并更新派生索引 | `draft accept` / 控制中心 |
| 草稿审批 | 决定是否接受一组文件变更 | 草稿状态 `draft`、`applied`、`discarded` |
| 事实核验 | 核实带逐字原文引句的 `source_claim`，并记录依据和结论 | `.llm-wiki/reviews.json` 与 `wiki/reviews.md` |
| 待补充 | 处理资料缺口、外部查证问题和旧版无引句审核项 | `.llm-wiki/reviews.json` 与 `wiki/reviews.md` |
| 回收站 | 隐藏资料的派生页面和检索结果，可恢复 | `state.json` 的 `trash` 状态 |

## 状态边界

```text
收件箱 -> 已归档 -> 分析中 -> 草稿待确认 -> 已应用
                              |-> 已丢弃
                              |-> 失败，可重试
已应用 -> 已移入回收站 -> 已恢复
```

- 归档和分析快照可以立即发生；模型页面、索引、概览、日志和审核 / 研究项只能在应用草稿时写入。
- 草稿审批不代表资料事实已经核实。只有 `source_claim` 有非空原文引句且工具能在原始资料中找到该逐字引句时，才能进入“事实核验”；其他模型问题进入“待补充”。
- 核验时先打开原始资料和当前 Wiki 页面，确认工具显示的行号和原文引句；处理任何队列项目都必须写明依据、结论或后续动作。
- 已有人手修改的页面与草稿基线不一致时，应用必须失败。重新生成草稿或人工合并后再继续。
- 页面重新生成会保留未知 frontmatter 键和 `## 人工补充` 段。
