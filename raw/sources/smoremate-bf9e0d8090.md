# SmoreMate 项目介绍

状态：产品概述与落地场景说明  
日期：2026-07-24

## 1. 项目定位

**SmoreMate** 是一款面向**私有化部署**的**端侧垂类 Agent 工作台**：不做公有云 SaaS，也不做「什么都能干」的通用 Agent 平台，而是把**特定行业/岗位的高价值工作流**（如工业 AI 方案评审）打包成可现场部署的专项 Agent，跑在企业自己的机器上。

当前市面多数 AI 助手和 Agent 产品默认走**公有云 API**——对话、材料、检索索引经过第三方基础设施，对工业方案、客户标书、内部技术文档等敏感场景存在**数据出境、留存不可控、合规难审计**等风险。SmoreMate 选择相反路径：**模型、材料、RAG、工具、运行记录全部留在客户内网**；单实例只服务一家企业，数据边界清晰。

产品形态上，SmoreMate 更像**可部署的垂类 Agent 套件**，而非开放式平台：


| 维度  | 公有云通用 Agent（主流）    | SmoreMate（私有化垂类 Agent）                     |
| --- | ------------------ | ------------------------------------------ |
| 部署  | 多租户 SaaS，数据经公有云    | 客户现场私有化，可断外网                               |
| 场景  | 横向通用，靠 Prompt 临时拼装 | 纵向深耕，预置场景包 + 可复用专家                         |
| 硬件  | 依赖云端大模型            | **消费级显卡**（如单卡 24GB 级）即可支撑团队级垂类任务           |
| 交付  | 注册即用               | **FDE 式交付**：负责私有化模型部署、`ai-proxy` 路由网关与场景落地 |


**FDE（Forward Deployed Engineer）式交付**是本项目的商业抓手之一：客户不必自行选型模型、搭推理集群、写路由网关、再拼 Agent 工作流。由我方驻场或远程完成「**模型部署 + 网关路由 + SmoreMate 安装 + 垂类场景包配置**」的一体化交付，让客户在可控硬件和数据边界内直接用起来。

工业 AI 方案评审是**首个垂类场景包**，验证「消费级显卡 + 私有化模型 + 专业Agent」的可行性；工作台底层的对话、专家、材料、工具能力可复用于后续更多垂类包。

差异化价值可以概括为四点：


| 维度   | SmoreMate 的做法                                            |
| ---- | -------------------------------------------------------- |
| 数据边界 | 端侧私有化部署，材料与推理不出客户网络；不做公有云多租户                             |
| 垂类深度 | 预置领域专家与专家团，固定工作流骨架，而非让用户从零 Prompt 造 Agent                |
| 硬件可达 | 针对垂类任务做模型选型与并发闸门，目标是在**消费级 GPU** 上稳定运行                   |
| 交付闭环 | 私有化模型 + `ai-proxy` 网关 + 应用 + 场景包由我方 FDE 交付，降低客户自建 AI 栈门槛 |


## 2. 市场背景

工业 AI 正处于高速增长期，本节先交代大盘价值与结构趋势，再定位本项目所处的细分坐标。

### 2.1 工业 AI 大盘：千亿级赛道，增速 20%–40%

「工业 AI」在不同研究机构中口径差异较大（是否含硬件、集成、工业软件、智算基础设施等），数字不宜直接横向对比，但**量级与增速共识明确**：


| 口径               | 规模（约）                              | 增速 / 预测   | 来源                                                   |
| ---------------- | ---------------------------------- | --------- | ---------------------------------------------------- |
| **全球工业 AI**      | 2024 年约 436 亿美元 → 2030 年约 1539 亿美元 | CAGR ~23% | IoT Analytics《Industrial AI Market Report 2025–2030》 |
| **全球制造 AI**      | 2025 年约 342 亿美元 → 2030 年约 1550 亿美元 | CAGR ~35% | MarketsandMarkets                                    |
| **中国工业 AI 解决方案** | 2025 年约 2010 亿元 → 2026 年约 2594 亿元  | 同比 ~29%   | 观知海内                                                 |
| **中国工业 AI（中口径）** | 2025 年突破约 1200 亿元                  | CAGR ~29% | 中研普华                                                 |


**大盘结论**：无论取宽口径还是中口径，工业 AI 均已进入**千亿级（人民币）/ 数百亿美元（全球）** 赛道，且未来 5 年保持 **20% 以上** 复合增长。制造业智能化、预测性维护、质检、供应链优化是主流应用场景；政策层面，「人工智能+制造」专项行动明确到 2027 年推广 **500 个典型应用场景**、培育 **1000 家标杆企业**，为行业提供持续需求侧牵引。

### 2.2 本项目所处细分：工业 AI 智能体与私有化垂类 Agent

SmoreMate 不覆盖整个工业 AI 大盘，而是聚焦其中增长快、私有化意愿强、尚未被公有云通用 Agent 很好满足的切片：


| 细分                 | 规模（约）                            | 渗透率 / 特征        | 与 SmoreMate 的关系                                           |
| ------------------ | -------------------------------- | --------------- | --------------------------------------------------------- |
| **中国工业 AI 智能体**    | 2025 年约 148 亿元 → 2026 年约 204 亿元  | 渗透率约 7%–8%，仍处早期 | 同属 Agent 形态；SmoreMate 偏**知识工作流 Agent**（方案评审），而非产线控制 Agent |
| **中国工业大模型（窄口径）**   | 2025 年约 17 亿元 → 2030 年约 420 亿元   | CAGR >90%       | 垂类模型 + 场景落地需求与 SmoreMate 方向一致                             |
| **工业大模型相关支出（宽口径）** | 2025 年约 890 亿元 → 2030 年约 4800 亿元 | CAGR ~40%       | 含 AI 中台、嵌入式工业软件等；SmoreMate 可视为其中「私有化场景包」的一种交付形态           |


**细分结论**：工业 AI 智能体中国市场 2025 年约 **150 亿元级**，渗透率不足 **10%**——说明大盘虽热，但**真正落到岗位级 Agent 的渗透仍很低**。通用大模型「一通百通」在工业场景频频碰壁，行业报告普遍指出竞争焦点正从「算法能力」转向**懂场景、能落地、敢承诺效果**，以及**垂直 Know-how 深度适配**。

### 2.3 结构趋势：私有化、边缘侧、垂类化

与 SmoreMate 定位高度相关的三个市场信号：

1. **数据不出域驱动私有化**：工业方案、客户标书、工艺参数等核心材料在军工、能源、制造、政企等场景**不能上传公有云**；公有云 Agent 越强，这类客户的「可用 AI 缺口」反而越大。
2. **边缘 / 端侧部署加速**：2025 年边缘侧小参数工业大模型部署量同比增长超过 **120%**，边缘部署占比已超过云侧 **55%**；模型压缩使单次推理成本降至 2023 年的 **1/5 以下**，消费级显卡即可支撑垂类任务——与「端侧专项 Agent + 消费级 GPU」路线吻合。
3. **行业专用模型份额上升**：行业专用模型市场份额从 2024 年约 **18%** 升至 2025 年约 **31%**；需求侧从「买一个大模型」转向「买一个能用的场景」——与 FDE 式「模型 + 网关 + 应用 + 场景包」交付模式一致。

### 2.4 SmoreMate 的市场坐标

用 TAM → SAM 框架概括 SmoreMate 可触达范围（数量为量级估算，用于对内对齐与对外叙事，非财务预测）：

```text

  └── 中国工业 AI 解决方案 ~2000 亿元/年（2025）
        │
SAM（可服务的细分市场）
  └── 工业 AI 智能体 + 私有化知识工作流 Agent ~150–200 亿元/年（2025）
        │     售前/方案/技术评审等「材料敏感 + 流程固定」岗位
        │
SOM（近期可拿下）
  └── 工业 AI 方案评审场景包 + FDE 交付
        首批：已部署或愿意部署本地模型的制造企业、集成商售前与解决方案团队
        单客户：消费级 GPU 工作站 + 私有化全套，按项目/年费计
```


| 层级       | 含义                                    | SmoreMate 切入点             |
| -------- | ------------------------------------- | ------------------------- |
| **大盘价值** | 工业 AI 是确定性高增长赛道，政策与降本增效双轮驱动           | 赛道够大，值得做垂类深耕而非泛化平台        |
| **细分价值** | 智能体渗透率 <10%，私有化 + 垂类是公有云未覆盖的空白        | 首发工业方案评审，再复制场景包           |
| **近期变现** | FDE 交付「模型 + 网关 + 工作台 + 场景包」，按客户现场落地收费 | 不依赖公有云按量 API，客单价与数据合规诉求匹配 |


**与大盘的关系**：SmoreMate 分享工业 AI 高速增长的红利，但**不参与**公有云通用 Agent 的红海竞争；而是在千亿大盘中，切取「**数据不能出域 × 岗位级垂类 Agent × 消费级硬件可部署 × FDE 交付**」这一高价值细分。首发场景「工业 AI 方案评审」落在研发设计 / 方案交付交叉带——虽非当前工业大模型应用中占比最高的生产环节（约 46%），但**材料敏感度高、私有化意愿强、交付单价可观**，更适合作为首个场景包验证商业闭环。

## 3. 解决了什么问题？

### 3.1 核心矛盾：想用 AI，但不敢把数据交给公有云

今天大多数 AI 助手和 Agent 产品走**公有云 API** 路线。对企业客户而言，这意味着：

- **方案、标书、客户资料、内部评审意见**等核心材料要上传到第三方；
- 数据**留存周期、训练用途、跨境传输**难以约束，审计链条不完整；
- 一旦涉及军工、能源、制造、政企等行业的合规要求，公有云方案往往**直接不可用**。

SmoreMate 要解决的第一个问题：**在数据不能出域的前提下，让企业团队仍然能用上够用的 AI 能力**——不是退回到「完全不用 AI」，而是在客户自己的机器上跑垂类 Agent。

### 3.2 第二个矛盾：通用 Agent 太宽，垂类工作流太深

公有云上的通用 Agent（聊天 + 插件 + 自由编排）看似万能，落到具体岗位却常出现：

- **不懂行业语境**：工业方案评审要同时看需求覆盖、数据可行性、算法指标、架构安全、交付验收，通用助手容易漏掉阻断级问题；
- **方法不可复用**：评审清单、分析框架散落在个人 Prompt 里，换人就失效；
- **平台过重**：桌面控制、插件市场、任意代码执行带来安全责任，与「只要一个能审方案的 Agent」的真实需求不匹配。

SmoreMate 的第二个问题：**把 AI 从「通用聊天」收敛为「可部署的垂类专项 Agent」**——预置专家、固定专家团骨架、内置 Skill，让用户直接调用场景，而不是每次从零拼装。

### 3.3 第三个矛盾：私有化想做，但自建 AI 栈门槛太高

即便客户认同私有化，落地仍卡在：


| 卡点               | 具体表现                            | SmoreMate + FDE 交付的应对                     |
| ---------------- | ------------------------------- | ----------------------------------------- |
| **模型不会部署**       | 选型、量化、推理服务、显存调优需要专业团队           | 我方负责私有化模型部署与 `ai-proxy` 路由网关，按场景匹配模型别名与能力 |
| **硬件预算有限**       | 企业级 GPU 集群成本高，小团队难以立项           | 面向**消费级显卡**做模型与并发设计，单工作站即可支撑团队级垂类任务       |
| **Agent 工作流不会搭** | RAG、工具调用、Multi-Agent 编排每个项目重复集成 | SmoreMate 提供对话级 RAG、受限工具循环、专家团编排，场景包开箱即用  |
| **治理与合规**        | 既要 AI 辅助，又要防止管理员偷看业务内容          | 单企业实例、内容隔离、无内容审计；材料归属对话、删除即清理             |


### 3.4 痛点对照（产品层）

在上述矛盾之下，SmoreMate 在产品层进一步解决：


| 痛点           | 具体表现                         | SmoreMate 的应对                            |
| ------------ | ---------------------------- | ---------------------------------------- |
| **模型选不对**    | 普通用户不了解上下文窗口、工具调用、结构化输出等能力差异 | 运行前**模型能力门禁**；`Auto` 映射 FDE 配置的默认别名      |
| **长材料难处理**   | 方案文档动辄数十页，上下文装不下             | **对话级 RAG**：按 Token 预算自动全文注入或检索，材料不出对话边界 |
| **多角色评审易遗漏** | 人工逐项检查耗时，阻断级问题仍可能被漏掉         | **Multi-Agent 专家团**：固定角色并行 + 团长汇总，带证据引用  |
| **失败不可见**    | 云 Agent 常静默降级，用户以为成功其实漏了关键步骤 | **失败要明确**：材料缺失、工具失效、成员失败则整体失败，不伪成功       |


**一句话**：SmoreMate 解决的是——**公有云 Agent 数据不可控、通用 Agent 不够垂、私有化自建门槛太高**这三重矛盾。通过**端侧垂类 Agent + 消费级显卡可部署 + FDE 式一体化交付**，让客户在自有数据边界内获得够用的专项 AI 能力。首发场景是**工业 AI 方案评审**。

## 4. 用了什么 AI 技术？

SmoreMate 不训练自有基座模型，而是在企业内网边界内，把多种成熟 AI 能力编排为受控工作流：


| 技术                  | 在 SmoreMate 中的用法                                                                   |
| ------------------- | ---------------------------------------------------------------------------------- |
| **本地大语言模型（LLM）**    | 通过 `ai-proxy` 调用客户现场私有化模型；按垂类场景选型与量化，目标适配**消费级 GPU** 显存与吞吐                         |
| **领域 Agent（专家）**    | 将角色目标、工作方法、示例问题固化为可复用专家定义；运行前快照锁定配置，模型按每次运行选择，不绑死在专家上                              |
| **Multi-Agent 协作**  | 专家团采用固定骨架：团长规划子任务并生成可校验执行计划 → 固定成员并行分析 → 团长汇总；非自由自治 Agent 网络，避免不可控行为               |
| **对话级 RAG（检索增强生成）** | 长材料经独立 RAG 底座预处理与分块；按运行 Token 预算在**全文注入**与**对话材料检索**间自动切换；懒创建对话级临时知识空间，不形成跨对话企业知识库 |
| **工具调用（Tool Use）**  | 受限工具循环：模型请求 → 工具执行 → 结果回传，有轮数上限；内置 Skill（任务方法包）+ 管理员配置的只读 MCP 工具                   |
| **结构化输出与证据引用**      | 专家团规划/汇总依赖 JSON Schema；输出带 `EvidenceRef`，可追溯材料片段或 RAG Chunk 来源，支撑评审结论可验证           |
| **长对话上下文管理**        | 用户可见的结构化摘要 + 最近完整问答轮次参与后续运行；摘要可查看和修正，避免超长对话超出模型窗口                                  |
| **模型能力门禁**          | 运行前确定性匹配工具调用、结构化输出、上下文窗口与本次任务（含专家团固定成员池），不兼容则明确拦截                                  |


技术选型遵循「**垂类够用、端侧可部署、边界清晰**」：不追求云端超大模型全能对话，而是为特定场景匹配合适规模的私有化模型；不引入跨对话向量记忆、任意代码执行或开放式 Agent DAG，把复杂度集中在**FDE 可交付、数据不出域、质量可验证**上。

## 5. 商业与业务价值

SmoreMate 的商业逻辑不是「卖一个 SaaS 账号」，而是**私有化垂类 Agent 的产品化 + FDE 式现场交付**。

### 5.1 市场价值：公有云 Agent 繁荣下的「数据出域」空白

- **赛道背景**：工业 AI 大盘中国约 **2000 亿元/年**、全球数百亿美元，增速 20% 以上；工业 AI 智能体细分中国约 **150 亿元/年**，渗透率不足 10%——详见 [§2 市场背景](#2-市场背景)。
- **目标市场**：对**数据主权和合规**有硬性要求、又希望引入 AI 提效的企业团队；首批切入售前、解决方案、技术架构等**材料敏感、流程固定、可垂直打包**的知识工作。
- **需求痛点**：不是「没有 AI」，而是「**不敢用公有云 AI**」+「**通用 AI 帮不上具体岗位的忙**」——需要一个能放在自己机房里、懂自己场景的专项 Agent。
- **首发场景**：工业 AI 方案评审——读取客户方案材料，输出带证据引用的多维度评审报告；与人工流程**影子并行**，不参与批准/驳回，降低采纳风险。

### 5.2 落地能力：消费级硬件 + FDE 交付，降低私有化门槛

- **硬件可达**：不做「必须采购 A100 集群」的方案。针对垂类 Agent 任务做模型选型、量化与**实例级并发闸门**，使**消费级显卡**（如单卡 24GB 级工作站）即可支撑小团队日常使用——这是相比公有云和大集群私有化方案的显著降本点。
- **FDE 式交付闭环**：客户无需自建 AI 基础设施团队。我方交付范围包括：
  1. **私有化模型部署**（选型、推理服务、显存调优）；
  2. `ai-proxy` 路由网关（模型别名、能力目录、并发与路由策略）；
  3. **SmoreMate 应用安装**（Web 工作台、RAG、工具、治理）；
  4. **垂类场景包配置**（预置专家、专家团、评测基线）。
- **渐进采纳**：先影子试用验证质量，再扩大使用范围；场景包可按行业复制，工作台底座无需重复建设。
- **行业扩展**：工业 AI 是首个场景包；同一套「端侧部署 + 垂类 Agent + FDE 交付」模式可复用到其他材料密集、流程固定的垂直场景。

### 5.3 产品体验：垂类 Agent 开箱即用，而非从 Prompt 造 Agent

- **场景直达**：用户选择「工业 AI 方案评审团」即可启动多角色分析，不需要理解 Multi-Agent 编排；
- **材料就地处理**：上传方案文档后在本地完成解析与检索，不经过外部 API；
- **结果可交付、可追溯**：结构化报告 + CSV 矩阵 + `EvidenceRef` 证据引用，支撑评审结论被业务方采信；
- **失败透明**：材料缺失或成员失败时明确报错，避免「看起来完成了其实漏检」。

### 5.4 技术实现：端侧可部署的 Agent 编排，而非云端重型平台

- **先进性**：受限 Multi-Agent、对话级 RAG、工具调用、结构化输出、SSE 流式状态、运行恢复与 GPU 并发闸门——在私有化环境下提供接近云端 Agent 的编排体验。
- **克制**：不做公有云多租户、不做 Skill 市场、不做外部系统写入；**把算力和数据留在客户侧**，用垂类深度换横向广度。

### 5.5 创新性：「端侧垂类 Agent + FDE 交付」的组合

- **与公有云通用 Agent 的差异**：不是比谁模型更大，而是比**数据是否出域、场景是否够深、落地是否够轻**。
- **与自建私有化平台的差异**：客户买到的不是一堆开源组件清单，而是**已调通的模型 + 网关 + 垂类工作流**，由 FDE 负责交付和调优。
- **方案巧思**：专家团用**固定成员池 + 可校验计划**控制端侧模型的不可预测性；在消费级硬件约束下，用并发闸门和模型能力门禁保证稳定而非盲目追求并行度。

### 5.6 商业模式与可量化收益


| 维度         | 价值                                                   |
| ---------- | ---------------------------------------------------- |
| **客户付费逻辑** | 私有化部署 + 场景包 + FDE 实施/运维，替代「公有云 API 按量付费 + 数据风险自担」    |
| **降本**     | 消费级 GPU 即可起步，无需为通用 AI 立项大集群；减少每个项目重复集成 RAG/Agent 的人力 |
| **合规**     | 材料、推理、索引、审计全在客户内网；可断外网运行，满足数据不出域要求                   |
| **提效**     | 垂类专家团一次提交产出多维度评审，关键问题召回目标高于通用助手（质量优先于速度）             |
| **资产沉淀**   | 领域专家定义可在企业内共享复用，从个人 Prompt 升级为可治理的垂类 Agent 资产        |


## 6. 核心功能

### 6.1 统一对话入口

- 用户点击「新建任务」即创建一个**私有对话**，对话承载消息、运行结果、任务材料和内部产物。
- 同一对话可跨轮次切换**通用助手**、**单专家**、**专家团**和**模型**，无需重建上下文。
- 每个对话同一时间最多一个活动运行；不同对话可并行处理多个任务。
- 长对话通过**用户可见的结构化摘要** + 最近完整问答轮次参与后续运行，摘要可查看和修正。

**适用场景**：售前跟进、方案迭代、多轮澄清、跨角色切换的复杂任务，而不必为每次切换重建会话。

### 6.2 模型选择与能力门禁

- 通过企业本地模型网关 `ai-proxy` 统一调用，v1 仅使用 Chat Completions 协议。
- 每次运行可选择 `Auto` 或指定模型；`Auto` 映射到管理员配置的唯一默认别名。
- 运行前做**模型能力门禁**：工具调用、结构化输出、上下文窗口与本次任务（含专家团固定成员池）做确定性匹配，不兼容则禁用并给出原因。

**适用场景**：避免普通用户误选不支持工具或上下文不足的模型；专家团规划/汇总依赖 JSON Schema 输出时，系统自动拦截不兼容模型。

### 6.3 可复用专家体系

三类专家并存：


| 类型              | 说明                          |
| --------------- | --------------------------- |
| **通用助手**        | 系统内置，承担普通对话，不可删除            |
| **预置专家**        | 系统管理员维护，全企业可见；首批含 8 位工业场景专家 |
| **私有 / 企业共享专家** | 成员自建，可无需审批直接共享给企业           |


专家定义包含角色目标、工作方法、示例问题；工具白名单由系统治理。每次运行写入**不可变快照**，后续编辑不影响已提交任务。成员可复制预置或共享专家为私有副本。

**适用场景**：把领域方法论（需求分析、架构评审、交付评估等）固化为可复用 Agent，在团队内传播最佳实践，而不把 Prompt 散落在个人聊天记录里。

### 6.4 预置专家团

v1 预置 **「工业 AI 方案评审团」**，采用固定协作骨架：

```text
团长规划 → 固定成员并行执行 → 团长汇总
```

- **团长**（方案负责人）：拆分子任务、生成结构化执行计划，不直接调用工具。
- **固定成员**：需求分析、数据可行性、算法评估、系统架构、项目部署安全——每次运行全部参与，用户不能增删替换。
- 成员彼此隔离并行，只向团长提交结果；任一固定成员失败则整体失败，不以部分结果拼接替代。
- 输出带 `EvidenceRef` **证据引用**，可追溯材料片段或 RAG Chunk 来源。

**适用场景**：需要多角色、多维度交叉检查的方案评审，比单专家或通用助手更能召回「关键问题」（需求缺口、数据不可行、架构风险、交付隐患等）。

### 6.5 任务材料与对话级 RAG

- 支持 TXT、Markdown、CSV、DOCX、文本 PDF、基础 XLSX 等格式。
- 原文件保存在 S3 兼容对象存储（如 MinIO）；解析统一走独立 **RAG 底座** 的无状态预处理 API。
- 按运行 Token 预算自动选择**全文注入**或**对话材料检索**；需要检索时懒创建对话级临时知识空间。
- 用户可管理**活动材料集**（启用/停用），运行快照锁定当时的材料状态。

**适用场景**：评审客户需求文档、方案草稿、技术附件等长材料任务；材料只在当前对话内有效，不形成跨对话企业知识库。

### 6.6 受控工具与内部产物

- **内置 Skill**：随版本发布的任务方法包（如需求覆盖矩阵、工业可行性检查、证据化风险评审），不执行任意代码。
- **MCP 工具**：系统管理员配置远程 Streamable HTTP MCP Server，仅批准**只读**工具；可接入企业全员可读知识检索（可选）。
- **受限工具循环**：有轮数上限的「模型请求 → 工具调用 → 结果回传」，参数与权限校验失败只允许一次纠正。
- **内部产物**：Markdown 报告、CSV 矩阵、JSON 结构化结果等，在 SmoreMate 内预览和下载，不写入外部系统。

**适用场景**：在评审中生成需求覆盖矩阵、风险清单等结构化交付物，同时避免 Agent 随意修改 CRM、发邮件或执行代码。

### 6.7 身份、权限与治理

- **OIDC + BFF 会话**：浏览器只持有服务端不透明 Cookie，不透传 OIDC Token。
- **两类业务角色**：成员（默认）、系统管理员；另设独立的**应急管理员**（密码 + TOTP，仅用于初始化或 SSO 故障恢复）。
- 系统管理员可治理用户、预置内容、MCP、工具启停和**无内容运行审计**，**不能查看**成员对话、材料、回答或产物。
- 专家/工具**治理停用**会立即取消相关活动运行；成员**本地停用**会取消其全部活动任务。

**适用场景**：满足企业内「能用 AI 辅助工作，但管理员不能偷看员工内容」的合规预期。

### 6.8 运行调度与可靠性

- PostgreSQL 持久化运行状态、租约队列和事务发件箱，不依赖 Redis/Kafka。
- **实例级模型调用并发闸门** + 用户公平轮转，保护本地 GPU/推理容量。
- 服务重启后可恢复排队任务；取消、删除、治理停用采用单调终态，迟到结果不能改写状态。
- 浏览器通过 SSE 接收流式状态；断线不取消后台运行。

**适用场景**：多用户并发使用、长时专家团运行、服务维护后任务不丢失。

## 7. 主要落地场景

### 7.1 工业 AI 方案评审（首发核心场景）

**谁在用**：售前、解决方案、技术架构师

**输入**：客户需求摘要、方案草稿、技术附件（DOCX/PDF 等）

**怎么用**：

1. 新建对话，上传方案材料；
2. 选择「工业 AI 方案评审团」+ 合适模型（需支持工具与结构化输出）；
3. 提交评审任务，等待规划 → 五角色并行分析 → 团长汇总；
4. 查看带证据引用的评审报告，展开各成员提交结果。

**产出示例**：

- 按阻断/高/中/低分级的关键问题摘要
- 需求覆盖矩阵（CSV）
- 数据与算法可行性评估
- 架构与项目部署安全风险
- 交付与验收风险
- 待客户澄清问题清单

**价值**：把原本依赖人工逐项检查的评审流程结构化、可复用；与现有人工流程**并行**（影子评审），不参与批准/驳回，降低引入风险。

**质量目标**：在可控评测案例上，专家团对「关键问题」的召回率应高于通用助手和最佳单专家。

### 7.2 单专家深度分析

**谁在用**：熟悉某一领域的业务或技术人员

**输入**：对话描述 + 可选材料

**怎么用**：从预置或企业共享专家库选择对应角色（如「数据可行性专家」「系统架构专家」），单独运行。

**适用**：只需某一维度深挖、不需要完整专家团开销的任务；或专家团前的预研与聚焦。

### 7.3 通用对话与轻量任务

**谁在用**：所有成员

**怎么用**：默认「通用助手 + Auto」，进行问答、起草、整理、简单分析；成员可自建私有专家覆盖写作、翻译等通用场景。

**适用**：日常知识问答、文档润色、会议纪要整理（v1 不预置此类专家，由通用助手或自建专家承担）。

### 7.4 企业内专家知识沉淀与共享

**谁在用**：领域骨干创建，团队成员复用

**怎么用**：

1. 成员将成熟的工作方法写成专家定义；
2. 一键改为「企业共享」，全公司可见；
3. 其他成员可复制为私有副本再定制。

**适用**：把团队最佳实践（评审清单、分析框架、输出模板）从个人 Prompt 升级为可治理、可审计的企业资产。

### 7.5 带长材料的文件任务

**谁在用**：需要阅读大量文档的角色

**怎么用**：在对话中上传多份材料，管理活动材料集；系统自动按上下文预算选择全文或 RAG 检索。

**适用**：合同条款比对、技术规范查阅、多文档交叉引用；材料归属对话，删除对话即清理，符合数据最小化。

### 7.6 私有化现场部署

**谁在用**：对数据出域敏感、希望 AI 跑在自己机房或办公室工作站上的企业团队

**典型硬件**：消费级 GPU 工作站（如单卡 24GB 显存级），由 FDE 完成模型量化与并发配置，无需先行采购企业级 GPU 集群。

**交付组件**（我方 FDE 负责模型与网关，客户侧仅需提供机器与网络）：

```text
客户现场（可断外网）
  ├── 消费级 GPU 工作站
  │     └── 私有化模型推理服务
  ├── ai-proxy（模型路由网关，我方部署配置）
  └── SmoreMate（Web + API + Worker）
        ├── PostgreSQL（元数据、队列、审计）
        ├── MinIO / S3（原文件与产物）
        ├── 独立 RAG 实例
        ├── 企业 OIDC IdP（可选）
        └── 可选 MCP Server（企业只读知识检索）
```

**适用**：方案/标书/客户资料不能上传公有云；希望「买来就能用」的垂类 Agent，而非自行拼装开源组件；愿意以 FDE 方式完成首套落地与调优。

## 8. 总结

SmoreMate 的定位是**私有化部署的端侧垂类 Agent**，直面当前主流公有云 Agent 的结构性问题：**数据出域风险、场景过宽不落地、客户自建 AI 栈门槛过高**。工业 AI 大盘中国约 **2000 亿元/年**、智能体细分约 **150 亿元/年**且渗透率不足 10%（见 §2），为垂类私有化 Agent 提供了足够大的赛道与早期窗口。

我方以 **FDE 式交付**提供完整闭环——私有化模型部署、`ai-proxy` 路由网关、SmoreMate 工作台与垂类场景包——让客户在**消费级显卡**即可起步的现场环境中，获得数据不出域的专项 AI 能力。工业 AI 方案评审是首个验证场景；工作台底座可复用于更多垂直行业包。

**最适合的客户**：核心材料不能上公有云、希望要「懂业务的 Agent」而非「万能聊天」、愿意以私有化 + 现场交付方式采纳 AI 的企业团队。

**当前阶段**：v1 以内部验证和影子试用为主，验证消费级硬件上的垂类 Multi-Agent 质量与 FDE 交付流程的可复制性。
