# InfiniBand 技术详解：从架构到原理

## 1. 概述

**InfiniBand（缩写为 IB）** 是一种**高性能、低延迟、高可靠性的网络互连技术**，主要用于**高性能计算（HPC）**、**人工智能（AI）** 和**大规模数据中心**场景。核心设计目标：**为计算节点（服务器、GPU）、存储设备之间，提供一条极速且稳定的数据传输通道。**

## 2. 诞生背景

在 90 年代末，CPU 和内存性能高速增长，但连接它们的 I/O 总线（如 PCI）速度跟不上，形成了“I/O 瓶颈”。于是，1999 年由 Compaq、IBM、Intel、Microsoft 等巨头牵头成立了 **InfiniBand 行业协会（IBTA）**，旨在设计一种替代传统 PCI 总线的新一代互联标准。Intel 等公司转向发展 **PCIe** 总线，但 InfiniBand 凭借其出色的技术特性，被保留并发展为**计算机集群互联**的专用技术，最终称霸了 HPC 和 AI 领域。

## 3. 核心架构

### 3.1 点对点交换架构

与传统的共享总线不同，InfiniBand 采用 **点对点（Point-to-Point）** 的连接方式。每个设备都通过交换机矩阵（Switch Fabric）互连，拥有自己的专用通信通道，数据可以并行传输，不存在总线争用问题。

### 3.2 核心硬件组件


| 组件          | 英文                           | 功能描述                             |
| ----------- | ---------------------------- | -------------------------------- |
| **主机通道适配器** | Host Channel Adapter (HCA)   | 服务器端的智能网卡，执行 RDMA 等硬件卸载任务，是性能核心。 |
| **目标通道适配器** | Target Channel Adapter (TCA) | 用于连接存储设备、I/O 设备，功能比 HCA 简化。      |
| **IB 交换机**  | IB Switch                    | 负责子网内部数据包的快速转发。                  |
| **IB 路由器**  | IB Router                    | 负责连接不同的 InfiniBand 子网。           |


> 注意：InfiniBand 交换机**只实现物理层和链路层**，不涉及复杂的网络层处理，从而保证极致的转发速度。

## 4. 分层协议栈（Protocol Stack）

InfiniBand 协议采用分层结构，下层为上层提供服务。


| 层级       | 主要功能                                                   |
| -------- | ------------------------------------------------------ |
| **物理层**  | 定义线缆、光模块、电气信号，负责将数据编码成比特流传输。                           |
| **链路层**  | 定义数据包（Packet）帧格式，负责子网内路由、流量控制。**这是实现无损网络的关键层。**        |
| **网络层**  | 负责不同子网（Subnet）之间的路由，封装**全局路由报头（GRH）**。                 |
| **传输层**  | 将数据可靠、按序地投递到正确的应用程序队列（QP），负责报文分段、重组、多路复用。              |
| **上层协议** | 提供标准接口，如 **IPoIB**（在 IB 上运行 IP 协议）、**SDP**（Socket 加速）。 |


## 5. 核心通信机制：应用程序直接访问硬件

### 5.1 队列对（QP, Queue Pair）

QP 是应用程序与 HCA 硬件通信的接口。每个 QP 由两部分组成：

- **发送队列（SQ）**：存放应用程序发出的数据发送请求。
- **接收队列（RQ）**：存放接收数据的缓冲区信息。

应用程序通过“工作请求（Work Request）”将任务提交到 QP，HCA 硬件会自动完成后续传输，无需操作系统干预。

### 5.2 Verbs 接口

Verbs 是一组标准的软件 API 函数，应用程序可以通过调用 Verbs 来操作 QP，与 HCA 硬件直接通信。

### 5.3 RDMA 与零拷贝（Zero-Copy）

**远程直接内存访问（RDMA，Remote Direct Memory Access）** 是 InfiniBand 最核心的技术：

- 数据**直接从一台机器的内存传输到另一台机器的内存**。
- **完全绕过操作系统内核和 CPU**。
- 避免了数据在“内核缓冲区 → 应用程序缓冲区”之间的多次复制（即“零拷贝”）。

这使得 CPU 可以专注于业务计算，同时将网络延迟降低到 **2 微秒以下**。

## 6. 无损网络的基石：信用流控

### 6.1 基于信用的链路层流控

传统以太网在拥塞时会直接**丢弃数据包**（有损网络）。而 InfiniBand 通过 **基于信用的流控机制** 实现了**无损（Lossless）**：

1. 接收方会预先告知发送方自己的可用缓冲区大小（信用值，Credit）。
2. 发送方**严格根据信用值**发送数据。
3. 只有当接收方有足够的缓冲区时，数据才会被发送。

这从物理层根本上杜绝了因接收方缓冲区满而导致的丢包。

### 6.2 虚拟通道（VL, Virtual Lane）

一条物理链路上可以划分为多个逻辑上的虚拟通道（VL），每个 VL 都有独立的缓冲区并独立进行信用流控。

- **隔离流量**：不同 VL 的流量互不干扰。
- **QoS 保障**：可为关键流量（如 RDMA 写）分配高优先级 VL。
- **防止队头阻塞**：一个 VL 的拥塞不会阻塞其他 VL 上的流量。

## 7. 拥塞控制与网络管理

### 7.1 拥塞控制

信用流控虽然防止了丢包，但可能引发**拥塞扩散**（一个节点拥塞，通过“反压”效应影响上游节点）。InfiniBand 规范定义了**拥塞控制机制**：

- 交换机检测到拥塞时，会主动在数据包上打上标记（FECN/BECN）。
- 接收端收到标记后，告知发送端网络拥塞。
- 发送端主动降速，从源头缓解拥塞。

### 7.2 子网管理器（SM, Subnet Manager）

子网管理器是 InfiniBand 网络的“大脑”：

- 发现网络拓扑。
- 为每个设备分配唯一的 **本地 ID（LID）**。
- 计算并配置交换机路由表。
- 持续监控网络状态，保障高可用。

## 9. InfiniBand vs. 以太网


| 对比维度        | InfiniBand                           | 以太网（含 RoCE）              |
| ----------- | ------------------------------------ | ------------------------ |
| **设计目标**    | 极致性能，专为 HPC/AI                       | 通用兼容，普适性强                |
| **RDMA 支持** | 原生硬件 RDMA，性能最优                       | 需 RoCE 支持，依赖无损网络配置       |
| **延迟**      | < 2 微秒                               | 约 5 微秒（RoCE v2）          |
| **丢包机制**    | **无损网络**，硬件信用流控                      | **有损网络**，需 PFC 等额外机制实现无损 |
| **拥塞控制**    | 硬件级 IB CC 机制                         | 依赖 DCQCN 等软件算法           |
| **生态与成本**   | **高成本、封闭生态**（主要由 NVIDIA/Mellanox 提供） | **低成本、开放生态**，多厂商可选       |


## 10. 总结：InfiniBand 的设计哲学

InfiniBand 通过以下设计，构建了不同于传统以太网的极致性能体系：

1. **通信模式**：从“操作系统处理”变成“**应用程序直达硬件**”。
2. **数据传输**：通过 **RDMA + 零拷贝**，实现高效的内存间数据交换。
3. **网络可靠性**：通过硬件级 **信用流控**，从底层保证**无损**。
4. **性能隔离**：通过 **虚拟通道（VL）**，提供 **QoS** 并避免 **队头阻塞**。
5. **拥塞管理**：通过 **IB CC**，防止 **拥塞扩散**。
6. **网络管理**：通过 **子网管理器**，实现 **集中式智能管理**。

在现代大型数据中心中，InfiniBand 通常与以太网共存：**InfiniBand 负责高性能计算网络（计算集群互联），以太网负责存储网络和管理网络**。
